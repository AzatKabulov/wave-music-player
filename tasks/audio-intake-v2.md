# Personal audio staging — 2026-10-27

The focused personal catalog now contains **58 popular recordings**, 24 artists, 51 release entries and six playlists. Twenty-eight new recordings and their covers were added after a stopped-service backup and a successful import on a copied database. All existing 75 playlist entry identities/positions were retained. Account preferences, saved entities, personal playlists and playback-session/queue state hashes stayed unchanged.

The offline inspector accepts local MP3, AAC/M4A and canonical PCM WAV sources with explicit intended durations. It bounds file size and external-tool execution, hashes bytes, checks container/codec agreement, sample rate/channel count and genuine video exclusion, then fully decodes the audio. Both container duration and decoded duration must match the intended recording within a bounded tolerance. FFmpeg receives local file/pipe protocols only. Original source bitrate/container are recorded; no nonexistent alternate rendition is advertised.

`scripts/inspect-audio.mjs` is the reusable operator entry point. Configure `MUSIFY_FFMPEG_PATH` and `MUSIFY_FFPROBE_PATH` to trusted local executables, then run it with a local file and expected milliseconds. The portable FFmpeg 9.0.2 archive came from [Gyan's Windows builds](https://www.gyan.dev/ffmpeg/builds/), linked by [ffmpeg.org](https://ffmpeg.org/download.html). Its archive SHA-256 was verified before execution and recorded in the evidence. Binaries and private media stay outside Git and the mobile build archive.

Staging uses ordinary public download anchors and separate official metadata/artwork identities. It checkpoints each validated result. A repeated pass re-hashed covers and fully re-decoded all 28 cached recordings without downloading again. Eight candidates without exact exposed download matches and the unavailable Frank Ocean page remain outside this batch. The final count falls within the owner's 50–70 testing scope.

Tests cover HTML responses, wrong hashes, duration mismatch, video and failed/short decodes. Real FFmpeg checks accept a genuine two-second intro and reject that short file against a full-song expectation, a bad checksum and a deliberately truncated compressed recording. All new covers were fully decoded, measured and assigned versioned palettes. The live LAN check verifies all 58 recordings by search, full audio/artwork hashes, thumbnails and beginning/end ranges. The temporary verification account was deleted afterward. The current personal bootstrap is 87,474 bytes; this small-catalog result does not close V04's large-library scaling acceptance.

Explicit/clean edition and cross-source recording identity have not been independently fingerprinted. New records retain unknown explicit provenance alongside the source metadata's explicit flag. Selected songs remain partial albums unless their source-backed expected member count is present. Broader C04 acceptance still requires dedicated interrupted-download/retry/quarantine tests and rendition staging; C05 still needs portraits/biographies/credits.
